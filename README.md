# СайтКонтроль 1.6.1

Android-приложение для проверки доступности сайтов по HTTP и HTTPS. Оно хранит список адресов и последний результат, проверяет сайты по расписанию и вручную, уведомляет о восстановлении доступности.

**Ревью кода и вычистка багов:** Yury Myshinskiy.

## Использование

Нажмите «+» и добавьте адрес. Без указания протокола применяется HTTPS. Карточка показывает результат, HTTP-код или тип ошибки и время проверки. Нажатие на карточку проверяет один сайт, кнопка «Проверить сейчас» проверяет весь список. Для удаления нажмите «×» в карточке и подтвердите действие.

В настройках доступны интервалы от одной минуты до трех часов. Когда интерфейс закрыт, Android WorkManager использует минимум 15 минут и может задерживать запуск. Уведомление появляется при переходе сайта из недоступного состояния в доступное; на Android 13 и выше требуется разрешение.

HTTP по умолчанию запрещен. Его можно разрешить после подтверждения риска в настройках. Это разрешение действует на все HTTP-адреса списка. Переход с HTTPS на HTTP остается запрещен. Заблокированная проверка имеет состояние POLICY и отдельно учитывается в статистике.

Не используйте для мониторинга адреса, которые изменяют данные на сервере при GET. HTTP после разрешения остается незашифрованным. Проверки выполняются из сети телефона и не подтверждают доступность сайта из других сетей.

## Защита данных

В уведомление передается только имя узла. Путь, параметры запроса и фрагмент адреса исключены. Для закрытого экрана задан общий текст; его фактическое отображение зависит от системных настроек.

Данные исключены из системного резервного копирования и переноса между устройствами. Уже созданные старой версией копии приложение не удаляет. Полные адреса сохраняются в закрытом хранилище Android без дополнительного шифрования самим приложением. Не помещайте в них секреты без необходимости.

Список сайтов, идентификатор приложения ru.sitewatch.monitor и формат хранения сохранены. После перехода с версии без отдельного согласия запрет HTTP немедленно отражается в карточках. Отзыв разрешения HTTP проверяется перед каждым следующим запросом в цепочке перенаправлений.

## Установка и обновление

Минимальная версия Android: 6.0, API 23. Версия приложения: 1.6.1, versionCode: 8. Целевой API: 36.

APK подписан ключом выпуска. Для обновления уже установленного экземпляра требуется та же подпись. Если прежний APK был собран другим ключом, Android откажет в установке поверх него. Не удаляйте прежнюю установку до сохранения списка сайтов; при удалении локальные данные теряются.

Исходный ключ подписания и пароли в репозиторий и выпуск не входят. Для собственных выпусков используйте свой закрытый ключ и сохраняйте его для следующих обновлений.

## Сборка

Нужны Java 17, Android SDK Platform 36 и SDK Build Tools 36.0.0. Откройте папку проекта с settings.gradle в Android Studio. При первой сборке потребуется интернет.

Для macOS и Linux:

```sh
./gradlew --no-daemon --dependency-verification strict testDebugUnitTest assembleDebug assembleRelease bundleRelease lintDebug lintRelease
```

Для Windows:

```bat
gradlew.bat --no-daemon --dependency-verification strict testDebugUnitTest assembleDebug assembleRelease bundleRelease lintDebug lintRelease
```

Результаты: app/build/outputs/apk/debug/app-debug.apk, app/build/outputs/apk/release/app-release-unsigned.apk и app/build/outputs/bundle/release/app-release.aab. Файлы release по умолчанию не подписаны. Скрипт tools/sign_release.py подписывает APK или AAB с паролем из локального файла. Ключи и пароли не входят в репозиторий. APK из раздела Releases уже подписан. AAB предназначен для загрузки в Google Play и не устанавливается напрямую.

Применяется Android Gradle Plugin 9.5.0. Сборка использует Gradle 9.8.2 с заменой встроенной Guava на исправленную 33.7.2-jre. Это измененный комплект инструментов для проекта. Официальный Gradle Wrapper не изменен; его JAR и архив инструментов закреплены контрольными суммами.

[Происхождение и изменения инструментов](docs/TOOLCHAIN.md) · [Контрольные суммы инструментов](tools/toolchain.json) · [Уведомления о сторонних компонентах](NOTICE.md).

## Проверки

В проекте 16 автоматических тестов правил адресов и сетевых запросов. Отдельный сценарий tools/emulator_smoke.py проверяет подписанный APK на изолированном эмуляторе: обновление с исходников 1.3, сохранение шести сайтов и интервала, согласие на HTTP, ошибки, уведомление без секретов, принудительный запуск фоновой задачи, отступы API 36 и доступность политики конфиденциальности. Для версии 1.6.1 прошли 11 групп проверок. Дополнительно APK из AAB проверяется на отдельном образе Google Play.

Сценарий сбрасывает только тестовую установку СайтКонтроля на эмуляторе и требует явного флага --reset-test-app. Он отказывается работать с физическим устройством. Адреса и секреты в проверках синтетические.

Для автоматической проверки на GitHub подготовлен шаблон tools/github-actions.example.yml: сборка, тесты, Android Lint, повторное создание архива инструментов и проверка известных уязвимостей по OSV. Действия закреплены SHA коммитов, ключ подписания не используется. Шаблон не активирован в этой публикации: действующий доступ к GitHub не включает разрешение workflow. Локальные проверки и испытания эмулятора выполняются независимо от этого шаблона.

Подтвержденные результаты текущего выпуска и ограничения приведены в [отчете о проверках](docs/TESTING.md). Отсутствие совпадений в OSV не гарантирует отсутствия неизвестных уязвимостей. Работа на физических телефонах и ограничения энергосбережения производителей требуют отдельной проверки.
